# Frontend agent contract

Frozen by `scoutlens-uze.2` on 2026-08-04. Decision record: `D033` in
[`decisions-log.md`](decisions-log.md).

This contract lets a specialist frontend agent pick one ready bead and execute
it end to end without authority over scientific semantics, published data or
release thresholds. It is binding for any agent or human executing a child of
`scoutlens-uze`, and it is subordinate to a current instruction from the user or
the repository's `AGENTS.md` / `CLAUDE.md`.

If this contract and a bead disagree, the bead loses and the executor stops.

---

## 1. File ownership

Three levels. **Allowed** = edit freely within the bead's stated scope.
**Conditional** = edit only when the bead names the exact file and the named
reviewer has approved. **Denied** = never edit in a frontend bead; crossing the
line stops the task.

reason to cross a line.

### Scientific invariants

A frontend bead may change **how** a value is presented. It may never change:

- any metric, rank, cosine, percentile, z-score, support count or uncertainty
  value, or its unit, rounding or precision;
- a metric id, feature id, evidence id, caveat code or claim string;
- the ordering the artifact supplies (retrieval rank, neighbor rank, feature
  family order);
- which caveats are rendered, or the conditions under which one is shown;
- the fail-closed behaviour of checksum, schema or manifest validation;
- the dataset version pin.

Removing a caveat to make a layout fit is a stop condition, not a trade-off.

## 2. Three boundary scenarios, resolved

These are the cases that would otherwise be argued case by case.

**A. Presentation-only component markup — proceed.**
Changing an element, adding a wrapper, reordering DOM, adding an ARIA attribute
or splitting a component is Allowed, provided the rendered text, the values, the
number of caveats and the semantic reading order are unchanged. Reading order
must change in the **DOM**, never via CSS `order` alone, so assistive technology
and visual order stay in agreement. Evidence: a DOM-text diff showing only
structural changes.

**B. Evidence-loading or content change — stop and escalate.**
Any edit under `web/src/content/**` or to `showcase-repository.ts` that changes
what is loaded, when it is validated, or what a value means requires the bead to
name the file and the reviewer to have approved before work starts. A pure
formatting helper (for example, adding `tabular-nums`-friendly formatting that
does not alter the produced string) is Conditional, not Allowed — the bead must
still name it.

**C. Generated contract or artifact change — always blocks frontend execution.**
If the work needs a new field in `web/src/contracts/generated/showcase.ts`, a new
artifact file, or a change to a schema, the frontend bead **stops**. Record a
dependency on the owning `scoutlens-jtt` bead and hand back. This is never
bundled into a frontend PR, and it is never worked around by casting, optional
chaining over a missing field, or a local type widening.

## 3. Delivery protocol

1. **One bead, one branch, one PR.** Branch from the current integration branch,
   named for the bead id. The PR body links the bead and lists nothing else.
2. **No concurrent edits to the same layer.** Before claiming, check that no
   other bead is `in_progress` against the same route or the same CSS layer file
   from §4. If there is, take a different bead. `scoutlens-uze.4` (shell,
   landing, science) and `scoutlens-uze.5` (lab) are explicitly parallelisable
   because their layer sets are disjoint.
3. **Preserve an unrelated dirty worktree.** Stage only the files the bead owns.
   Never `git add -A`, never `git checkout --` a file you did not change, never
   stash someone else's work. If an unrelated modification is present, say so in
   the handoff and leave it alone.
4. **Never commit, push, or run `bd dolt push` without current authority.** The
   default is conservative: report the proposed commands and stop. Authority
   from one session does not carry to the next.
5. **Run the gates the bead names**, at minimum `pnpm lint`, `pnpm typecheck`,
   `pnpm test` and `pnpm build`. Quote the actual output; "tests pass" without a
   command and a result is not evidence.
6. **Fail closed on scope.** If the fix needs a Denied file, stop with partial
   work rather than widening the diff.

## 4. CSS target map

Frozen selection for `scoutlens-uze.3`. Today `web/src/app/globals.css` is 2,654
lines and 400 top-level rules with no section markers, and ownership interleaves
throughout the file — so the extraction must be **selector-driven, not
line-range-driven**.

`research-story.css` is deliberately **not** split into landing and science:
`research-story.tsx` is rendered by both routes, so a route-named file would give
two beads a claim on the same rules and break §3.2.

`lab.css` is deliberately **not** split further, even though it is the largest
file. A selector-driven split into selector / profile / neighbors would leave 11
selector lists spanning two or three of the new files — for example
`.lab-selector, .selected-profile, .lab-state` (line 1122),
`.retrieval-boundary, .neighbor-drawer__header` (line 2568) and the four-way
`48rem` group at line 2533. Splitting a selector list across files duplicates
declarations and reorders them, which is exactly what a zero-visual-change pass
must not do. The split also buys no concurrency: `scoutlens-uze.5` owns the whole
Lab, so no two beads compete for it. Revisit only if a second Lab bead is ever
created, and then split at those 11 seams deliberately.

`.research-step__marker` lives in `science.css`, not `primitives.css` — it is the
element in defect F-1 of [`frontend-qa-audit.md`](frontend-qa-audit.md), owned by
`scoutlens-uze.4`.

### 4.2 Rules the extraction must follow

1. **Intra-layer source order is preserved verbatim.** Rules move between files;
   they never reorder within a file.
2. **Media queries are distributed into their owning layer and placed at the end
   of that file**, `64rem` block before `48rem` block, matching the current file.
3. **No declaration is edited, added, removed or reformatted.** Not a shorthand
   expansion, not a colour notation change, not a reindent.
4. **No `@layer`, no `:where()`, no specificity rewriting.** Those change cascade
   semantics and are out of scope for a mechanical move.

### 4.3 Why the reorder is safe, and how to prove it

A per-owner split cannot preserve global source order, because ownership
interleaves. A reorder changes rendering only when two rules (a) can match the
same element, (b) declare the same property, and (c) have equal specificity, and
the split flips their relative order.

Static analysis over all 473 selectors under the order in §4.1 found **0 such
pairs** and **0 unassigned selectors** (`scoutlens-uze.2`, 2026-08-04). This is a
conservative static result, not a proof: it approximates "can match the same
element" by requiring compatible ancestor chains, and it does not model dynamic
class composition.

So `scoutlens-uze.3` must confirm it empirically, and that is its acceptance
evidence: for every route and every audited state, snapshot
`getComputedStyle()` for **every** element before the split and after it, and
require a byte-identical diff. A visual screenshot comparison is not sufficient —
a sub-pixel cascade change can pass a 3% pixel threshold.

### 4.4 Dead rules — delete, do not move

**22 fully dead rule blocks, 2,839 bytes (5.6% of the stylesheet)**, reference
classes that no component renders. `scoutlens-uze.3` deletes them rather than
carrying them into a layer file; deleting a rule that matches nothing is a
zero-visual-change operation and is in scope for the mechanical pass.

`.metric-grid`, `.metric-card`, `.metric-card__value`, `.metric-card h3`,
`.metric-card > p:last-child`, `.principle`, `.principle > p`, `.lab-frame`,
`.lab-frame__status`, `.status-dot`, `.step-list`, `.step-list li`,
`.boundary-note`, `.boundary-note h2`, `.boundary-note p`, `.research-arc`,
`.research-step`, `.research-step h2`, `.research-step p:last-child`, plus their
own entries in the two media blocks.

**Two traps — partially dead shared selector lists.** `.step-list span,
.research-step__marker` (line 419) is a shared list: only the `.step-list span`
half is dead, and `.research-step__marker` carries the live `/science` marker
styling that defect F-1 depends on. The `48rem` block at line 2488 groups
`.metric-grid, .step-list, .experiment-grid, .experiment-grid--three` — the two
`.experiment-grid` halves are live. Split these two rules and keep the live
halves in their owning layer (`science.css` and `research-story.css`
respectively); do not delete either wholesale.

`.experiment-card--signal`, `.experiment-card--warning`, `.caveat--critical`,
`.research-stage--warning`, `.lab-state--integrity` and
`.lab-state--incompatible-data` look unreferenced to a plain grep but are
composed at runtime through template literals. They are **live**. Any future dead
-CSS check must account for dynamic composition before deleting anything.

## 5. Snapshot policy

1. A baseline is updated only when the bead's diff is the cause. Regenerating
   because a snapshot is red is prohibited.
2. Every update ships an **enumerated intended-difference list**: one line per
   changed region, naming the component, the property that changed and why.
   "Layout updated" is not an entry.
3. Before/after images for each updated baseline go in the PR, at each viewport
   the baseline covers.
4. Unrelated regions of an updated snapshot must be unchanged. If they moved,
   the diff is larger than the bead.
5. `maxDiffPixelRatio`, Lighthouse minimums and the budgets in
   `quality-budgets.json` may not be raised to make a run green. Masking a region
   to hide a diff is prohibited.
6. Platform baselines (`{projectName}-{platform}`) are reviewed independently.
   Updating `win32` does not authorise updating `linux` unseen.

<the bead id to depend on, and the reviewer, if a boundary is hit>

---

## 7. Definition of Done

- Every acceptance criterion is mapped to evidence: a command and its output, a
  measured number, or a named screenshot. No criterion is closed on assertion.
- Gates run with their real output quoted. Deviations (environment, skipped
  gate) are stated, not omitted.
- `git status` is reported. Files the bead does not own are untouched and their
  presence is called out.
- Follow-up work is filed as beads, not left as TODOs.
- The handoff names what was **not** done and why.
