# Player-disjoint representation benchmark — preregistered protocol

Frozen by `scoutlens-qop.1` on 2026-08-10. Decision record: `D041` in
[`decisions-log.md`](decisions-log.md).

**Protocol hash** `886ba315b587a91d0fa9ab5c7387f172f8957cf2cfde8a39a65216cb4ff31f1d`
**Split assignment digest** `715bdb90af59860c2510d6a69f43970c9734bef4e4e061740658d2496c30d96a`

This document is the preregistration for `scoutlens-qop`: does a learned
fingerprint representation retrieve the same player across a temporal split
better than the frozen Baseline B cosine metric, **on players never seen
during fitting**?

The decision rule below was fixed before any learned model was fitted. The
executable copy is
[`src/scoutlens/benchmark/protocol.py`](../src/scoutlens/benchmark/protocol.py);
this document explains it. If the two disagree, the module is authoritative —
it is what the hash is computed over.

---

## 1. Why this benchmark exists

The published temporal-retrieval result (`temporal-retrieval-within-role.md`)
is **descriptive**: it measures how well event-derived features recover "same
player" on the full eligible population, fitting the scaler on that same
population. That is a legitimate feasibility result and it is not a claim
about generalization.

`scoutlens-qop` asks a different, confirmatory question, and a confirmatory
question needs a different design: held-out humans, statistics fitted only on
training data, and a decision threshold written down before the answer is
visible.

## 3. The split

The unit is the **human**. Every `(player_id, competitionId, period)` row for
one player lands in exactly one split, so no model can be fitted on one half
of a person and scored on the other.

Assignment is deterministic without an RNG: each player's ordering key is
`sha256(f"{seed}:{player_id}")` with `seed = 2718`, ordered within role and
cut at `floor(n·0.60)` and `floor(n·0.80)`. The key depends on nothing but
the seed and the id — not row order, not population size — so re-running on
re-ordered input is byte-identical, and adding a player perturbs only its own
position.

### 3.2 Candidate pools are within-split

A query from split *S* is ranked only against period-B profiles of players in
*S*. Cross-split pools would let a test query retrieve a training player, and
would make pool size depend on split sizes.

> **Read this before comparing any number here to a published one.**
> Split-level absolute MRR is **not** comparable to the full-population
> figures in `temporal-retrieval-within-role.md`. The pools are smaller
> (753 / 251 / 253 versus 1,257), so retrieval is mechanically easier and MRR
> is mechanically higher. This is visible in §7: Baseline B scores 0.320
> within-role on train and 0.429 on validation, against 0.279 published on
> the full population. Nothing improved — the pool shrank. **Only the
> within-split paired delta (B − A) is the object of study.**

## 4. Preprocessing

Mean-impute, then z-score per feature. **The scaler is fit on the training
split only** and applied unchanged to validation and test.

This is a deliberate departure from D008, which fits on the population being
compared. D008 is right for a descriptive experiment and wrong for a
confirmatory one: it lets held-out rows inform the transform. A feature that
is all-null or zero-variance in train contributes exactly 0.

`tests/benchmark/test_leakage.py` proves this behaviourally rather than by
inspection — it corrupts every validation and test value by six orders of
magnitude and asserts the fitted scaler and the training metrics do not move.

**Fitted statistics are quantized to 12 significant digits.** Polars reduces
sums in parallel, so a mean or std over identical input can differ by 1–2
ULPs between runs. That never moves an integer rank — the metrics were
already bit-identical across runs — but it made the serialized scaler
irreproducible, and an artifact that cannot be regenerated byte-for-byte is
not publishable under the modeling contract (`D040` §4.1). Quantizing costs
~1e-12 relative on each z-score.

## 5. Features

**Primary: `CANONICAL_28`** — the frozen like-for-like set from
`statsbomb-feature-compatibility.md`, being the 32 Wyscout features minus
four: `smart_passes_p90` (unavailable on StatsBomb), `events_p90`

`CANONICAL_PLUS_CARRY` (30) and `CANONICAL_28` minus `touches_p90`.

## 6. Metrics and intervals

- **Primary:** within-role MRR.
- **Secondary:** global MRR, median rank, Recall@1 / @5 / @10.
- **Interval:** paired bootstrap over the shared query set, 1,000 resamples,
  seed 0, 95%, queries sorted by `(player_id, competitionId)` before
  resampling (D013).
- **Reference:** `baseline_b_cosine` over `CANONICAL_28` — the incumbent the
  representation must beat. `baseline_a_role_minutes` is reported as the
  floor that keeps the delta interpretable.

## 8. Subgroup rule — and a measured power problem

**The rule as preregistered:** report Baseline B per role; a role subgroup
gates the KEEP decision only when it has **at least 100 queries**.

**The problem, measured from §3.1 and stated here rather than discovered
later:** on the test split the largest role subgroup is Defender at **95**
queries, then Midfielder 90, Forward 48, Goalkeeper 20. **No role reaches
100.** As frozen, the subgroup criterion therefore gates on *zero* roles and
is inert.

This is exactly what a preregistration is for — the threshold and the split
were specified independently, and only writing both down at once makes the
interaction visible. Counting split sizes by role is design information, not
outcome information, so establishing this did not open the test set.

The number is **not** silently retuned here. `scoutlens-qop.1` implements the
threshold the bead froze. Changing a preregistered decision threshold is a
charter decision, not an executor's call, so it is routed to the bead author
as `scoutlens-qop.5` with the three options on the table:

1. lower the minimum to 50 — gates Defender, Midfielder and Forward, leaves
   Goalkeeper (20) reported but non-gating;
2. evaluate subgroups on pooled validation + test — restores Defender to 190
   and Midfielder to 180, at the cost of spending validation;
3. accept the criterion as inert and rely on the aggregate gates alone —
   honest, but drops the protection against a model that improves overall
   while degrading one role.

Until that decision is recorded, the aggregate KEEP gates in §9 are the
operative ones.

## 9. Decision rule

**KEEP** the learned representation only if **all** hold:

1. Wyscout **test** delta MRR ≥ **+0.020** over `baseline_b_cosine`;
2. paired 95% CI lower bound **> 0**;
3. no role subgroup with ≥ 100 queries drops more than 0.020 (see §8);
4. StatsBomb external delta **> 0** with 95% CI lower bound **> −0.010**;
5. operational budgets pass (§11).

**Otherwise DROP** — Baseline B stands.

+0.020 is a **practical**-significance floor, not a statistical one. A
statistically clean but smaller gain is a DROP: it does not justify replacing
a transparent cosine over named features with something harder to explain.
This is the project's standing position that a null result is a result.

### 9.1 Neural continuation gate

The neural contrastive arm (`scoutlens-qop.3`) runs **only** if the
interpretable diagonal model (`scoutlens-qop.2`) clears, on **validation**:

- delta MRR ≥ **+0.010** over `baseline_b_cosine`, and
- paired 95% CI lower bound **> −0.005**.

Otherwise: record the null and stop. This is the stop/go rule, not a
suggestion.

## 10. The test-set lock

The test split is shut until the protocol hash appears in
`docs/decisions-log.md`. This is mechanical, not a promise:
`assert_test_set_unlocked()` reads the ledger and raises otherwise, and
`evaluate_split(..., TEST)` additionally requires an explicit `allow_test`.
Two independent gates, so neither a stray argument nor an unrecorded protocol
alone is enough.

Editing `PROTOCOL` changes the hash and **re-locks** the test split. That is
intended: a protocol amended after seeing validation results is a different
protocol and needs its own decision record.

The test split is evaluated **once per candidate model**. A second look is a
new protocol version.

## 12. External test

StatsBomb 2015/16, competitions 2 / 7 / 11 / 12, `minutes_played >= 450` per
period, `CANONICAL_28` computed provider-natively. Weights are frozen from
the Wyscout training split; **nothing is refit on StatsBomb**. This is a
replication test, not a second training run.
